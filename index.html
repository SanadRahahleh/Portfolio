EduScope Case Study

Role: Backend Developer
Focus: Clean Architecture, Web API, Relational DB Design

Overview

EduScope is a structured educational system designed to coordinate session management, training agendas, evaluations, and programmatic structures. I worked primarily on the backend, focusing on building solid core layers, database integrity, security access levels, and REST APIs.

My Role

As the Backend Developer, I was responsible for designing and implementing the API structure, database schemas, and JWT security model. I operated within an Agile/Scrum team, translating functional requirements into structured database models and endpoints, validating data inputs, and ensuring strict role separation.

Architecture

The backend follows Clean Architecture principles, separating the system into logical layers:

  • Domain: Houses basic entities, schemas, and core models.
  • Application: Directs business cases, contracts, validation logic, and interfaces.
  • Infrastructure: Implements data access configurations, encryption, and external interfaces.
  • Web API: Handles HTTP endpoints, CORS rules, and middleware routing.

Backend

Built using ASP.NET Core Web API. The API is structured with custom model validations and centralized error-handling middlewares to format internal anomalies into clean HTTP status results, preventing raw server stack traces from being exposed.

Database

Designed the complete relational schema in SQL Server and mapped it via Entity Framework Core (Code First). Applied relational database rules:

  • Primary and Foreign keys to ensure absolute referential integrity.
  • Constraints to enforce range boundaries and string restrictions.
  • Logical data normalization to prevent duplication across records.

Security

Implemented secure system access using **JSON Web Tokens (JWT)** and **Role-Based Access Control (RBAC)**.

  • Supports separate roles: Admin, Trainer, and Student.
  • Tokens are signed server-side and contain user claims and permissions.
  • Controllers utilize strict authorization filters to ensure roles can only read or edit authorized data blocks.

Key Features

  • Session Management: Operations to build, update, and manage student training blocks.
  • Agendas: Structuring calendar events and schedules.
  • Evaluation Reports: Scoring grids and progress documentation.
  • Data Validation: Automated checks on request payloads before operations execute.

My Contributions

  • Constructed the complete SQL Server schemas and relations.
  • Wrote the repositories and database context classes using EF Core.
  • Developed backend modules for sessions, reports, and agendas.
  • Secured controllers and endpoints using RBAC filters.
  • Collaborated on user story refinement in Agile standups.

What I Learned

Deepened my practical understanding of separating software concerns under Clean Architecture. I learned to anticipate data boundary failures by adding strong validation checks, and gained confidence in creating highly structured, secure, and documentable APIs for client consumers.

Booking Management Service Case Study

Role: Backend Developer (.NET)
Focus: 3-Tier Architecture, Business Rules, Concurrency & Overlap Validation, Unit Testing

Overview

Booking Management Service is a backend system designed to solve resource-allocation conflicts in enterprise environments. It provides RESTful APIs for managing users, shared resources (meeting rooms, workstations, equipment), and reservations while safeguarding against schedule overlaps and double-booking errors.

My Role

As the Backend Developer, I built the system from scratch following 3-Tier Layered Architecture principles. I implemented the service interfaces, EF Core data contexts, double-booking validation algorithms, xUnit test suites, and a responsive frontend dashboard.

Architecture

The application is structured using a clean 3-Tier Layered Architecture to maintain a strict separation of concerns:

  • Controller Layer: Exposes clean HTTP endpoints (`UsersController`, `ResourcesController`, `BookingsController`) and formats JSON responses.
  • Service Interface Layer: Defines abstract contracts (`IBookingService`, `IResourceService`, `IUserService`) to decouples layers and facilitate unit testing.
  • Service Implementation Layer: Contains core application business logic, double-booking validation routines, and data transformations.
  • Data Access Layer: Manages SQL Server database operations using EF Core 10 `AppDbContext` and relational migrations.

Core Business Logic & Overlap Validation

The core challenge of resource booking is preventing scheduling conflicts. I implemented an algorithm that evaluates requested booking windows (`StartDateTime` to `EndDateTime`) against existing database records:

  • Overlap Prevention: Any new reservation is checked to ensure `(RequestedStart < ExistingEnd) AND (RequestedEnd > ExistingStart)` for the target resource.
  • Input Guardrails: Verifies that start dates precede end dates and rejects historical booking attempts.
  • Data Integrity: Foreign key relationships link bookings to verified users and active resources.

Automated Unit Testing

To ensure high system reliability, I authored automated unit tests using xUnit and EF Core InMemory Database:

  • Verified successful booking creation for non-overlapping time slots.
  • Tested error throwing and HTTP 400 bad request responses when attempting conflicting bookings.
  • Validated edge cases such as exact boundary times and invalid resource IDs.

Key Contributions & Technical Highlights

  • Resource Management: Architected a RESTful backend service to manage bookings for shared organizational resources (meeting rooms, desks, and equipment).
  • Validation Logic: Engineered time-overlap validation logic preventing double-booking conflicts and invalid scheduling requests.
  • Architecture & Design: Implemented 3-Tier Layered Architecture utilizing Dependency Injection, Service Interfaces, and EF Core ORM for clean maintainability.
  • Automated Testing: Authored automated unit tests using xUnit and EF Core InMemory database to validate core business rules and edge cases.
  • Frontend Integration: Built a lightweight web dashboard (HTML5, CSS3, ES6 JavaScript) communicating with backend API endpoints.

What I Learned

This project deepened my expertise in designing bulletproof business logic for scheduling systems. I learned how to isolate service contracts for seamless unit testing and gained hands-on experience structuring a production-ready 3-Tier architecture in .NET 10.
